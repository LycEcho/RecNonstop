## 三、“80%”的可检查口径

这是用户提出的目标，不是一个已经被证明成立的通用能力等式。必须分维度、分数据范围报告。

| 维度 | 检查内容 |
| --- | --- |
| 转写 | 字错率 CER；数字、专名、弱语音、静音和重叠语音单列，不用语义改写后的文字冒充原识别结果 |
| 事实覆盖 | 独立参考中的不同事项、数字、状态、否定、来源和时间是否被保留 |
| 任务保持 | 行动、责任归属、期限、接收者、条件及取消状态是否正确关联 |
| 忠实度 | 输出的事实性断言有无原文支持，有无补人名、日期、场景、关系、实施状态或后果 |
| 来源与场景 | 自述、新闻转述、剧情/广告、背景与不确定来源是否区分；声音标签不替代语义参考 |
| 可用性 | 原文覆盖、报告完整返回、失败提示、来源回看、手机实际显示及处理时间 |

现有分析/日报评分权重为事实 40、任务 30、忠实度 30；不适用项按既定规则处理。每个相关维度至少 80%，且关键错误为 0，才算对应案例通过。平均分不能掩盖关键错误；某案例加权总分超过 80 仍可能失败。

关键错误包括但不限于：把取消的安排变成执行任务、把引用当用户经历、丢失或反转必要前提、错配责任人、补出明确日期、无依据构造重要风险。是否属于关键错误以推理前冻结参考及独立评审为准，不能看结果后临时调整。

上线前要求完整回归中已知关键错误清零，新验收按同一口径通过；真实材料另外评分，不用合成结果替代。即使这些有限测试全部通过，结论也只能限定在已验证范围内，不能宣称所有使用场景达到助手能力的某个比例。

## 四、8GB 目标配置与验证

当前候选方向：ASR 保留 Qwen3-ASR-1.7B 的 Q8 解码器与 bf16 音频编码器，文本候选使用 4B Q4_K_M；文本分析不加载视觉编码器。第三方量化需记录发布者、固定版本和文件哈希。

备用对照为 Qwen3.5-9B 的第三方 Q4_K_M，权重约 5.29 GiB；ASR 与声音标签放 Linux CPU，目标 GPU 仅驻留文本模型。该方案尚在准备，权重加状态的估算不能代替 CUDA 工作区、完整上下文及 8GB 设备的实际峰值，也不能在质量评测前认定更优。只清理本次任务可重建的构建缓存准备空间，不删除录音、报告、源码或评测证据。

- ASR 上下文候选 4096，文本 8192、输出上限 4096；输入、提示和输出预算必须合计放入窗口。
- pipeline worker 为 1，共享推理并发为 1，服务并行槽为 1；这不保证模型能同时驻留 8GB。
- KV、批处理与 Flash Attention 参数须由所用后端实际支持；不能仅凭参数存在认定生效。
- 本轮保留非思考模式：有限思考对照仍有遗漏，不因“开启思考”自动改推荐。
- 实测要覆盖两模型驻留、最长上下文、ASR/日报交替、其他系统占用和持续运行，记录 OOM、排队、峰值和完成耗时。
- 只能使用宿主机现有推理/必要状态接口。不能为了做显存测试安装监控、修改模型或重启宿主机服务；当前权限下无法取得的指标标为未测。
