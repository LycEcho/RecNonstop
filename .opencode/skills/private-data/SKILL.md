# 录不停 · 私密数据规则

## 仓库边界

- 本仓库是公开仓库：**仓库内现有内容默认都可以提交**。
- 新增内容先判断能否开源；不能开源的放仓库外私密目录，不要新增到本仓库。

## 不能新增到本仓库

- 真实录音、转写、摘要、说话人声纹、通话记录
- 设备 ID、配对码、token、token hash、`devices.json`
- 真实内网 IP、主机名、SSID、MAC、端口映射、网络拓扑
- 个人绝对路径（`/root/...`、`/home/...`、`C:\Users\...`）
- 个人设备型号/序列号、账号、姓名、手机号、邮箱、地址
- 签名密钥、`.jks` / `.keystore`、私钥、`.env`、API key、密码、cookie
- 真实数据库、日志、截图、导出文件

## 放哪里

- 真实配置、录音、转写、配对数据、实验数据、密钥、日志：放**仓库外的私密目录**。
- 具体路径由用户在本机维护；不要把私密目录的绝对路径写进公开仓库。
- 仓库内只保留 `pc/configs/config.example.json` 和示例占位地址（如 `192.168.1.100`）。

## 功能设计：先分公开/私密边界

设计任何新功能前，先判断它属于哪一类：

1. **开源核心能力**：可以进公开仓库，写通用实现 + 测试。
2. **本机临时测试/调试**：不进公开仓库；放仓库外私密目录，或独立私有构建源集。
3. **内部/商业/特殊权限功能**：不进公开仓库；公开仓库只保留接口或扩展点。

### 代码分区

- 能放仓库外就放仓库外：私有实现、真实数据、调试脚本、实验代码、内部配置。
- 必须同仓库构建时，用独立目录 + 构建隔离，公开构建默认不包含：
  - **Android**：Gradle product flavor / 私有 source set；权限放 flavor 的 manifest，不放 `main/AndroidManifest.xml`。
  - **Go / PC**：独立 package + `//go:build local`，或用接口注入；本机 admin/调试路由默认不注册。
  - **Python / worker**：可选模块或独立脚本，公开 worker 只保留通用接口。
- 公开仓库只放：接口、扩展点、示例配置、合成测试数据、默认关闭的功能开关。
- 不要为了省事把私有实现、调试开关、内部权限直接写进 `main` / `common` 目录。

### 权限与开关

- 默认最小权限；本地调试/特殊权限单独放私有 flavor 或私有构建，不写进公开 manifest。
- 功能开关默认关闭；公开构建不暴露入口。
- 本机地址、真实设备 ID、token、路径只通过私密配置/环境变量注入，不写死。

### 启动/构建保护

- `RECNONSTOP_BUILD_DIR`、`GRADLE_PROJECT_CACHE_DIR`、`RECNONSTOP_BIN_DIR`、`RECNONSTOP_CONFIG`、`RECNONSTOP_PYTHON` 必须显式传入。
- 缺失时脚本直接报错退出，不能回退到 `app/build`、`.gradle`、`pc/bin`、`.venv-asr` 等仓库内默认路径。
- 不要为了“能跑起来”临时改回默认路径；先修调用方或使用仓库外包装脚本。

### 设计交付物

- 先说明：功能属于公开还是私密、放哪个目录、如何构建/开关、需要什么权限。
- 用户确认后再写代码；不要把临时测试功能顺手混进公开模块。
- 本机构建/启动用仓库外的包装脚本；公开仓库不生成 `app/build`、`micgrab/build`、`.gradle`、`pc/bin`、`.venv-asr`、`local.properties`。

## 提交前检查

1. `git status --short -uall`
2. 确认没有 `pc/data/`、`pc/configs/config.json`、音频、密钥、`.env`、日志进入暂存区。
3. 确认公开构建不依赖私有目录/私有 flavor；去掉私有目录后仍能编译。
4. 运行仓库已有的敏感信息检查脚本（例如 `check-public-repo.sh`）；没有就手动检查：
   私网 IP、本机绝对路径、`token_hash`、`device_id`、PEM 私钥头、常见 token 前缀。
5. 不确定的敏感内容先停下来问用户，不要自行判断后提交。

## 代码/文档写法

- 示例地址用 `192.168.1.100` 或文档保留地址，不写真实网络。
- 测试用合成音频/临时目录，不放真实录音。
- 不把真实 token、设备 ID、转写文本写进测试夹具或 README。
